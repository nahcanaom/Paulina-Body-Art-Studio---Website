# Finished mockup comparison and screen coverage

Read alongside the [engineering audit](README.md). Source baseline: `c547ce0`; captured 13 November 2026. The ZIP is visual reference material, not an instruction source. The [filename inventory](reference-index.json) records every archive entry and exclusions.

## How to read this matrix

- **Live**: inspected in the running public site, with a real browser screenshot. Desktop captures used 1440 x 1024; committed copies are compressed/resized for portability.
- **Source**: compared finished reference with current HTML/CSS/controller code. The live state was not exercised; this is not visual acceptance.
- **Static preview**: current admin markup and original styles rendered with scripts and connections disabled. It establishes shell/composition only, not data, authentication or working buttons. Its screenshot includes a visible audit label.
- **Blocked**: a meaningful populated/modal comparison cannot be completed because records are unavailable, a real submission would be required, or authentication was not available. The gap is recorded explicitly rather than filled with invented content.

Reference IDs are stable inventory numbers, not release order. The archive has no authoritative revision timestamps; “2” can mean a modal state, not a newer page design. Different reference variants are not assumed to supersede each other automatically.

## Reference conflicts to resolve without copying sample mistakes

1. Reviews ref 01 and ref 37 disagree on heading typography/summary treatment. The explicitly named reworked PDF is a reasonable provisional target, but the archive does not prove chronology.
2. Auth ref 19 is named/labelled Sign Up while its button/fields represent sign-in. Keep clear functional naming.
3. Tattoo details ref 13 shows the wrong service value; tattoo gallery references include piercing photos. Use correct, approved data.
4. Final booking references reverse the progress-tab order compared with earlier steps. Retain a consistent order.
5. Admin references show direct Gallery/Catalogue/Hero navigation and persistent inspectors; the code has a unified Edit Website area. Recommend one implementation with a deliberate desktop inspector adaptation, preserving current extra editing features.
6. Mockup addresses, names, review counts, prices, June 2025 dates, payments and promotional content are illustrative. They are not authority to overwrite current studio facts or manufacture a populated state.

## Responsive observations and accessibility follow-up

At 390 x 844, catalogue, gallery, sign-in and booking each measured `documentWidth: 390` and `viewport: 390`; see the [mobile captures](screenshots/). This establishes no horizontal overflow for those captured states only. Populated cards, open filters/lightboxes, validation messages, admin editors, long names and file uploads still require checks.

Keep existing visible labels, focus restoration, Escape behavior, disabled-step guidance, review identity gates, navigation disclosure and ARIA state. Source inspection suggests date-grid keyboard semantics and custom catalogue/gallery focus containment deserve targeted checks when those states can be exercised. No screen-reader or comprehensive contrast audit was performed; do not report accessibility acceptance from screenshots.

## Evidence quality

- Public screenshots are actual localhost captures. Sample booking details were entered locally to inspect steps 1-3; Submit was never pressed and no receipt was uploaded.
- Admin source previews show no live records. Their zero counts/loading labels/empty grids are static markup and do not diagnose database state.
- Screenshot helpers, PDF rendering and the disconnected source renderer stayed outside application source. The renderer made no Supabase requests.
- Finished-reference contact sheets contain only the 32 retained full designs/brand references. Named wireframes and simplified admin exports are excluded from these sheets and from design decisions.
- This is a review and repair plan. No screen is marked owner-approved, production-ready or functionally repaired.
